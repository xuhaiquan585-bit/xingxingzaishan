# 二维码标签印刷功能生产启用手册

状态：发布候选配套文档

适用范围：数据库迁移、功能启用、历史二维码分类和首批实体打样

限制：本文不构成生产授权，不包含密钥，不要求在本地发布候选阶段执行生产写入

## 1. 启用前条件

- 候选提交、Git tree 和迁移 `008_add_label_print_production.sql` 已固定并完成评审。
- 生产 PostgreSQL 已完成可恢复的站外备份，且备份对象、大小和校验值已核验。
- 生产应用配置保持 PostgreSQL 全量权威，`NODE_ENV=production` 时正式文件存储必须为私有 OSS。
- 管理员账号可用，公开扫码、短信、支付、上传和区块链健康状态均保持原基线。
- 旧“下载二维码图片”入口的退役行为已在候选环境验证为 HTTP 410。
- 首批实体打样只使用 10 个全新、未激活、已明确分类为可生产的二维码。

任一条件不满足即停止，不执行历史分类或正式文件生成。

## 2. 分阶段启用顺序

1. 记录当前应用提交、tree、进程和健康状态。
2. 执行并核验生产站外备份。
3. 仅应用新增迁移；此时不开放后台印刷入口。
4. 核对迁移版本、约束、触发器和历史二维码总数。
5. 部署应用候选并重启进程，确认本地与外部健康检查通过。
6. 打开标签模板和印刷任务后台入口。
7. 管理员按原二维码批次和 ID 前缀检查“历史未分类”列表。
8. 只将确认未印刷、未激活且可用于商品生产的具体 ID 标记为“可用于生产”。
9. 将测试码、来源不明码和确定不再使用的具体 ID 标记为“永久报废”，填写原因。
10. 确认旧高清导出接口保持退役，CSV 数据导出仍可用。
11. 发布首个 20 x 80 mm、600 DPI 模板版本。
12. 使用 10 个新二维码创建打样任务，生成一次正式 ZIP 并重复下载核对相同 SHA-256。
13. 交付打样，登记印刷中、合格 ID 和具体报废 ID。
14. 完成实体扫码、书写、裁切、圆角和一次激活验证后，才允许扩大批量。

## 3. 必须记录的验收证据

- 迁移前后数据库版本和迁移校验值。
- 历史未分类、可生产、已预留、文件已生成、已打印和已报废数量。
- 首个发布模板的模板 ID、版本、尺寸和服务端预览。
- 打样任务编号、二维码数量、正式 ZIP 大小、SHA-256 和下载次数。
- 两次下载的字节校验一致性。
- 10 张实体标签的扫码结果、书写效果和尺寸抽检。
- 取消前释放、生成后不可释放、印后逐码报废和重复激活拒绝的结果。
- 部署后应用健康状态和未受影响业务的冒烟结果。

证据不得包含二维码访问令牌、手机号、OSS 密钥或永久公开对象地址。

## 4. 停止与恢复边界

- 迁移失败：停止部署，按备份恢复流程处理，不继续启动新代码。
- 新代码健康检查失败且尚未生成正式印刷文件：回滚应用提交；新增表结构可保留待复查。
- 历史分类选择错误但事务尚未提交：取消操作；提交后分类不可反向修改。
- 正式文件生成失败：保留同一任务和预留，修复后仅重试同一任务；确认对象不存在时才可取消。
- 正式文件已经确认：不得释放、解绑或改绑二维码；只能继续使用或作废。
- 应用回滚发生在已有正式印刷事实之后：数据库约束不得回退到允许重新绑定的旧版本。
- 私有 OSS 对象存在但数据库没有引用：视为孤立对象，不得直接交付印刷；先核对任务身份、对象键、大小和 SHA-256。

## 5. 首批实体打样检查表

- 标签成品宽 20 mm、高 80 mm。
- 顶部 R3 mm、底部 R1 mm，裁切边不侵入内容。
- 二维码静区完整，普通手机在明暗环境下均可扫码。
- ID 与后台二维码 ID 完全一致，最长 ID 不溢出。
- 默认提示为“写下此刻，提交后仅可查看”，手写区可正常落笔且不易擦除。
- PNG 为 600 DPI，印刷厂未进行非等比缩放或二次二维码重绘。
- ZIP 只有 ID 命名 PNG 和 `二维码ID清单.csv`，清单不含令牌或手机号。
- 同一任务重复下载得到相同文件；二维码不能进入第二个印刷任务。
- 报废必须逐个 ID 登记；补印使用新二维码和新任务。
- 首次激活后，复制标签不能绑定第二件商品；正常重复扫码只能查看既有记录。

全部通过后，首批打样才可作为扩大正式生产的依据。
