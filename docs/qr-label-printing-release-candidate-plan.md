# 二维码标签模板与印刷生产管理系统

状态：本地发布候选实施合同  
范围：规格、PostgreSQL、服务端渲染、后台管理、测试和本地提交  
边界：不推送、不部署、不连接生产环境、不执行真实印刷或外部业务写入

## 1. 目标

建立从标签模板设计、二维码预留、正式生产文件生成、下载、印刷登记到具体二维码报废的闭环。正式生产文件是系统中唯一可用于印刷的高清标签来源；同一二维码不能进入两个印刷任务，同一印刷任务不能生成两份不同的正式文件。

首个默认模板固定为：

- 成品尺寸：宽 20 mm，高 80 mm。
- 顶部圆角：R3 mm。
- 底部圆角：R1 mm，视觉上保持方正。
- 正式输出：600 DPI PNG。
- 默认提示文字：`写下此刻，提交后仅可查看`，可在模板草稿中编辑。
- 上部包含二维码和二维码 ID，下部为手写留白区。

## 2. 非目标

- 不建立独立皮肤库；皮肤通过复制模板产生。
- 不建立印刷厂账号、门户或多级审批。
- 不做 A4/卷筒拼版、刀模计算、任意矢量绘图或多人协作。
- 不允许上传字体；正式字体随应用发布。
- 不做自动补印；补印必须创建新二维码并进入新任务。
- 不改变扫码、一次记录绑定、重复扫码查看、短信、支付、上传或区块链存证逻辑。
- 不把 CSV 数据导出解释为正式生产文件。

## 3. 数据权威与安全边界

- 新业务写入以 PostgreSQL 为唯一权威，不增加 JSON 业务权威。
- `qr_codes.issue_status` 继续表示发行状态，`lifecycle_status` 继续表示记录生命周期。
- `qr_codes.print_batch_id` 仅表示二维码当前且唯一的印刷任务归属。
- 新增独立 `print_status` 表示印刷生命周期，不复用发行或激活状态。
- 正式 ZIP 存入私有 OSS，数据库只保存对象键、大小、SHA-256 和生成事实；不公开永久 URL。
- SHA-256 仅用于确认同一正式文件的完整性，不扩展为重复审计体系。
- 后台正式文件下载必须通过管理员鉴权，由服务端读取既有对象并记录下载事件。
- 公开二维码接口不得返回模板、印刷任务、OSS 对象键或印刷状态。

## 4. 固定输出合同

- `px = round(mm / 25.4 * 600)`。
- 默认画布为 472 x 1890 px；PNG 必须写入 600 DPI 对应的像素密度元数据。
- 二维码使用真实访问内容重新生成，不缩放历史 PNG。
- 二维码必须保持正方形、黑白高对比和四模块静区。
- ZIP 内每张图片命名为 `<二维码ID>.png`。
- ZIP 内包含 UTF-8 BOM 编码的 `二维码ID清单.csv`。
- 清单列固定为：二维码 ID、PNG 文件名、原二维码批次、印刷任务编号、模板名称、模板版本。
- 清单不得包含访问令牌、手机号、OSS 对象键或其他敏感字段。
- 单个印刷任务最多 500 张。

## 5. 状态转换表

### 5.1 模板状态

| 当前状态 | 动作 | 前置条件 | 结果状态 | 可逆 | 失败处理 |
| --- | --- | --- | --- | --- | --- |
| 不存在 | 新建 | 管理员已登录；名称唯一 | 草稿 | 是 | 不创建记录 |
| 草稿 | 保存 | Schema、尺寸和元素合法 | 草稿 | 是 | 保留上次成功保存版本 |
| 草稿 | 复制 | 来源模板存在 | 新模板草稿 | 是 | 不创建副本 |
| 草稿 | 发布 | 服务端预览通过；二维码、ID、静区和尺寸约束通过 | 已发布 | 否 | 保持草稿并返回具体校验错误 |
| 已发布 | 创建新版本 | 模板未停用 | 新草稿版本 | 是 | 原发布版本不变 |
| 草稿 | 删除草稿 | 未被任何印刷任务引用 | 不存在 | 否 | 有引用时拒绝 |
| 已发布 | 停用 | 无需解除历史引用 | 已停用 | 否 | 保持已发布 |
| 已停用 | 查看历史 | 版本存在 | 已停用 | 不适用 | 只读失败不写入 |

约束：发布版本永久只读；所谓修改已发布模板，实际是创建一个新草稿版本。

### 5.2 印刷任务状态

| 当前状态 | 动作 | 前置条件 | 结果状态 | 可逆 | 失败处理 |
| --- | --- | --- | --- | --- | --- |
| 不存在 | 创建任务并预留 | 已发布模板；1 至 500 个可用二维码；事务锁成功 | 已预留 | 是 | 整个事务回滚，不保留部分预留 |
| 已预留 | 更新任务信息 | 未开始生成 | 已预留 | 是 | 保留上次成功内容 |
| 已预留 | 取消 | 未存在正式文件 | 已取消 | 否 | 同一事务释放二维码 |
| 已预留 | 确认生成 | 幂等键有效；二维码仍属于本任务 | 生成中 | 否 | 进入可恢复生成流程 |
| 生成中 | 上传并确认正式文件 | 全部 PNG 与清单生成；私有 OSS 不可覆盖上传和元数据校验通过 | 正式文件已生成 | 否 | 保持生成中，可用同一任务恢复；不得创建第二份逻辑文件 |
| 生成中 | 生成失败 | 数据库尚未确认正式文件 | 生成失败 | 是 | 保留预留；管理员重试或在无正式文件时取消 |
| 生成失败 | 重试生成 | 二维码和模板版本未变 | 生成中 | 否 | 继续使用同一对象键和同一任务身份 |
| 生成失败 | 取消 | OSS 与数据库均确认无正式文件 | 已取消 | 否 | 同一事务释放二维码 |
| 正式文件已生成 | 下载/重复下载 | 对象校验通过 | 正式文件已生成 | 不适用 | 不重新渲染；失败不增加下载次数 |
| 正式文件已生成 | 标记印刷中 | 正式文件存在 | 印刷中 | 否 | 状态不变 |
| 印刷中 | 完成登记 | 合格与报废具体 ID 覆盖任务全部二维码 | 已完成 | 否 | 校验失败则不写入 |
| 已完成 | 补登记印后报废 | 选择仍为已打印的具体 ID 并填写原因 | 已完成 | 否 | 任务保持完成，仅所选二维码永久报废 |
| 正式文件已生成/印刷中 | 整单作废 | 管理员确认 | 已作废 | 否 | 所有二维码永久作废，不释放 |
| 已完成/已作废/已取消 | 查看与审计 | 任务存在 | 原状态 | 不适用 | 只读失败不写入 |

提交边界：正式文件只有在私有 OSS 上传成功、大小和 SHA-256 校验成功、数据库将任务和所属二维码原子更新成功后，才被视为生成成功。数据库提交失败留下的对象是未被引用的孤立对象，不会成为可下载正式文件；恢复流程只能用同一任务对象键核验并完成提交，不能另建不同文件。

### 5.3 二维码印刷状态

| 当前状态 | 动作 | 前置条件 | 结果状态 | `print_batch_id` | 可逆 |
| --- | --- | --- | --- | --- | --- |
| 历史未分类 | 标记可用于生产 | 管理员一次性分类；未被印刷任务占用 | 未纳入印刷 | 空 | 否 |
| 历史未分类 | 永久作废 | 管理员确认具体 ID | 已报废 | 空 | 否 |
| 未纳入印刷 | 创建印刷任务 | 发行状态允许；未被占用 | 已预留 | 当前任务 | 生成前可通过取消释放 |
| 已预留 | 取消任务 | 正式文件尚未生成 | 未纳入印刷 | 空 | 是 |
| 已预留 | 正式文件确认 | OSS 与数据库提交边界满足 | 文件已生成 | 当前任务 | 否 |
| 文件已生成 | 标记印刷中 | 所属任务进入印刷中 | 文件已生成 | 当前任务 | 否 |
| 文件已生成 | 登记合格 | 选择具体 ID | 已打印 | 当前任务 | 否 |
| 文件已生成 | 登记损坏 | 选择具体 ID 和原因 | 已报废 | 当前任务 | 否 |
| 已打印 | 后续扫码/记录 | 继续使用现有生命周期规则 | 已打印 | 当前任务 | 不适用 |
| 已打印 | 质检后报废 | 管理员选择具体 ID 和原因 | 已报废 | 当前任务 | 否 |
| 已报废 | 任意印刷任务操作 | 永久终态 | 已报废 | 原值或空 | 否 |

数据库必须阻止：同一二维码同时预留到两个任务、正式文件生成后清空或修改 `print_batch_id`、已打印或已报废二维码重新预留、任务与二维码状态不一致。

## 7. 实施工作包与提交边界

1. 数据模型、迁移和状态约束。
2. 服务端模板 Schema、校验和渲染内核。
3. 模板库、桌面混合编辑器和服务端预览。
4. 印刷任务、唯一正式文件、下载审计和永久锁定。
5. 印刷结果、历史分类、旧入口切换、测试和发布文档。

每个工作包形成一个职责单一的本地提交。任何工作包都不得修改生产数据、调用生产 OSS 或改变现有扫码与区块链流程。

## 8. 验收矩阵

- 数据：迁移可在可丢弃 PostgreSQL 从空库应用；约束和触发器拒绝非法状态与改绑。
- 并发：两个事务争抢同一二维码，只允许一个任务成功。
- 模板：草稿可改，发布版本不可改，复制产生新草稿。
- 渲染：默认图为 472 x 1890 px、600 DPI、四模块静区；最长 ID 和提示文字不越界。
- 图片：Logo/背景格式、尺寸、像素和目标 DPI 不合格时拒绝发布。
- 任务：生成前取消释放；生成后只能下载、印刷、完成或作废。
- 幂等：同一任务重复生成不会得到第二份不同文件；重复下载返回相同字节。
- 报废：必须选择具体 ID；已报废二维码不能再次进入任务。
- 历史：迁移为历史未分类，不改变发行、激活、记录或存证字段。
- 性能：10、100、500 张记录耗时、峰值内存和 ZIP 大小；500 张不 OOM。
- 浏览器：桌面端模板编辑、发布、创建任务、筛选报废和下载状态完整可操作。
- 回归：受影响测试、迁移测试和完整 `npm test` 通过。

## 9. 失败恢复与回滚边界

- 数据库迁移只新增表、列、索引、约束和触发器，不重写用户记录或区块链数据。
- 服务端功能未开放前，新增结构可独立存在。
- 模板发布失败不改变草稿；任务预留失败整笔回滚。
- 正式文件生成失败保留任务与预留，允许从同一任务恢复或在确认无正式文件后取消。
- 正式文件一旦确认，不提供释放二维码的回滚路径。
- 应用代码可回滚到前一提交，但包含正式印刷事实的数据库不可回退到允许改绑的旧约束。
- 生产迁移、历史数据分类和实体打样均在本目标之外，由后续人工授权执行。

## 10. 完成报告要求

报告五个本地提交 SHA、迁移内容、测试结果、性能结果、样图路径、生产影响、迁移顺序、回滚边界和人工实体打样步骤。跟踪工作树必须干净，用户私有文件不得提交。
