- 未验证

- 本地通过

生产写入、外部付费调用、推送和部署需要独立授权。本记录中的本地通过不等于已经上线。

### 2026-10-02 最终候选代码边界复核

- 外部 Node 响应流现在对“未到 `end` 就提前 `close`”立即失败，不会留下永不结算的 Promise；成功、超限、错误和中断路径都会移除本读取器注册的监听器。
- Fetch 流在响应超限时显式取消 reader，即使调用者没有传入 `AbortController` 也不会继续下载剩余正文；声明长度超限和正常载荷行为保持不变。
- 有界乱码扫描发现 H5 与小程序各一处历史异常文案，均位于“登录身份存在但账号映射缺失”的失败分支；已恢复正常中文，并把两端公开文案加入真实 API 回归断言。修复后 `src` 与 `tests` 未再检出同类乱码特征。
- 修复配置与运行时偏差：短信冷却值 `0` 不再被 `||` 替换为默认 60 秒；限流桶在 `resetAt` 精确时刻开始新窗口，不再额外占用一毫秒旧窗口。
- 管理员与质检员令牌现在绑定账号当前的 `auth_version`、角色、用户名和启用状态；停用、重新启用或修改密码都会递增版本并立即使旧令牌失效，重新启用不会恢复旧令牌。管理员不能在当前会话中停用自己，避免误操作导致自锁。
- 管理员和小程序令牌解析均要求严格三段 JWT，附加多余段的畸形令牌不再被接受。部署该候选后，旧版本签发且不含 `auth_version` 的后台与质检令牌会按设计失效，相关操作员需重新登录；普通 H5 和小程序用户会话不受此次版本字段变更影响。
- 当前运行链路的备份、恢复演练、独立对象镜像、生产只读观察及隔离 PostgreSQL 验收 runner 现在要求完整干净工作树；除 `.gitignore` 明确排除的运行时数据外，已跟踪改动、暂存改动和未跟踪文件都会拒绝执行，避免服务器残留代码与所报告 commit/tree 不一致却仍给出 PASS。历史一次性迁移脚本未纳入本轮运行链路变更。
- 接口面重新枚举了 H5、小程序、后台、质检、支付与链回调的全部路由；未发现新增匿名业务写入或后台/质检角色绕过。全局解析错误现在把损坏 JSON 映射为 `400 INVALID_JSON`、把超限 JSON/表单正文映射为 `413 REQUEST_BODY_TOO_LARGE`，不再伪装成内部 500；文件上传超限继续使用既有 `UPLOAD_TOO_LARGE` 契约。
- 文件审计日志不记录请求正文或 Authorization，含扫码凭证的路径会先替换为固定占位符。支付业务日志此前会持久化完整微信解密通知，真实载荷可能包含付款人 OpenID、设备和客户端 IP；当前已在唯一数据库持久化入口改为字段白名单，只保留商户、订单、交易状态、时间和金额等对账必要字段。
- 自建小程序支付日志仍作为财务业务记录长期保留在当前 JSON 数据库中，写入会随数据库整体重写。当前平台店铺销售不经过该链路；若启用自建支付，必须先确定法定/业务保留期并迁移到可扩展的 PostgreSQL 日志表或等价存储，不能通过静默截断日志解决容量问题。
- JSON 兼容数据写入使用同目录独占临时文件、文件 `fsync`、原子替换、目录耐久化和两次源哈希冲突检查；写入或重命名故障后原文件及临时文件清理已有故障注入回归。新增的操作员 `auth_version` 允许旧数据缺省为 0，但负数、字符串、`null` 或非安全整数会在数据库启动/读取时明确拒绝，不再进入不确定令牌状态。

- 生产备份与恢复演练现在复用同一套有效运行配置重建和脱敏连接参数，不再假设数据库配置一定存在于进程初始环境。恢复演练已同步当前“链存证正常启用”的生产阶段，只声明 `BLOCKCHAIN_WRITE_BY_RUNNER=NONE`，不再把运行中的链服务错误标记为关闭。
